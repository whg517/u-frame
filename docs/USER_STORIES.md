## 1. 文档目的

本文档把 PRD 中的功能需求拆成可排期、可开发、可测试的用户故事。每个故事都包含来源需求和验收标准，用于产品评审、迭代计划、开发实现和验收测试。

用户故事描述业务结果，不替代技术设计。数据库、Tauri Command、目录结构和实现方案以技术设计文档为准。

## 2. 需求分析结论

### 2.1 用户角色

MVP 是本机单用户工具，不设计登录和角色权限。以下角色只用于描述使用目标，同一个实际用户可以承担多个角色。

| 角色 | 主要目标 |
|---|---|
| 运维管理员 | 建立机房和机柜结构，查看设备分布，完成上架、移动和下架。 |
| 资产管理员 | 维护设备台账，搜索核对资产，执行 Excel 导入导出。 |
| 本地数据管理员 | 创建备份、恢复数据并查看操作记录。 |

### 2.2 核心价值链

```text
建立机房和区域
  → 创建机柜
    → 建立设备台账
      → 分配 U 位
        → 在机柜一览中核对
          → 持续移动、下架、导入和备份
```

最小可用闭环不是单独的 CRUD，而是“创建机柜 → 创建设备 → 上架 → 在机柜画布看到正确位置”。

日常维护也不应被拆成彼此无关的页面。评估交互时以下列完整任务旅程为单位：

```text
从机房详情新增区域 → 从区域新增机柜 → 回到原位置继续工作
从机柜详情选择或新建设备 → 预选目标机柜 → 选择空闲 U 位 → 回到机柜
从画布选中设备 → 移动或下架 → 回到原筛选画布并看到结果
```

### 2.3 需求缺口与派生规则

分析 PRD 后补充以下规则。`DR` 表示从现有需求推导出的保守规则，并非新增产品范围。

| 编号 | 派生规则 | 理由 |
|---|---|---|
| DR-001 | 设备必须具有占用高度，默认 1U，且大于 0。 | 没有高度无法计算占用范围。已补入 PRD `AST-008`。 |
| DR-002 | 机柜缩容后如果会使现有设备越界，则拒绝保存并列出受影响设备。 | 保证已保存的放置关系始终有效。 |
| DR-003 | 已归档机房、区域、机柜和设备不可再新增下级对象或执行上架。 | 避免归档数据重新进入活动流程。 |
| DR-004 | Excel 中缺失的本地设备只标记为“缺失”，默认不自动归档或删除。 | 导入来源可能不是完整资产集，采用安全默认值。 |
| DR-005 | 名称、编码和唯一标识比较前先去除首尾空格；是否忽略大小写由实现保持一致。 | 防止肉眼相同但系统重复的数据。 |
| DR-006 | 设备归档和数据恢复必须二次确认；设备归档同时释放当前 U 位。 | 两类操作都会改变当前机柜视图。 |

### 2.4 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | MVP 必须完成；缺失时无法形成核心业务闭环。 |
| P1 | MVP 应完成；不阻塞最小闭环，但影响日常使用或数据可靠性。 |
| P2 | 可延期；主要改善信息完整度或操作效率。 |

## 4. EPIC-LOC：建立物理位置

### US-LOC-001 创建和维护机房

> 作为运维管理员，我希望创建、编辑和归档机房，以便按照真实物理地点组织机柜。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | LOC-001、LOC-003、LOC-004 |
| 前置条件 | 应用已正常启动 |

验收标准：

1. **Given** 当前不存在同名活动机房，**When** 用户填写有效名称并保存，**Then** 系统创建机房并在位置列表显示。
2. **Given** 同名机房已经存在，**When** 用户再次保存相同名称，**Then** 系统拒绝保存并标记名称冲突。
3. **Given** 机房尚无活动机柜，**When** 用户确认归档，**Then** 机房变为已归档且不再出现在默认活动列表。
4. **Given** 机房下仍存在活动机柜，**When** 用户尝试归档，**Then** 系统拒绝操作并提示需先处理相关机柜。
5. **Given** 机房已归档，**When** 用户查看历史数据，**Then** 原有信息仍可查询且未被物理删除。

### US-LOC-002 创建和维护区域

> 作为运维管理员，我希望在机房下维护区域，以便按楼层、房间或分区组织机柜。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | LOC-002、LOC-003、LOC-004 |
| 依赖 | US-LOC-001 |

验收标准：

1. **Given** 存在活动机房，**When** 用户输入区域名称并保存，**Then** 区域创建在所选机房下。
2. **Given** 同一机房下存在同名区域，**When** 用户保存，**Then** 系统拒绝重复名称。
3. **Given** 不同机房分别存在同名区域，**When** 用户保存，**Then** 系统允许创建。
4. **Given** 区域下仍有活动机柜，**When** 用户尝试归档区域，**Then** 系统拒绝操作并说明依赖关系。
5. **Given** 所选机房已经归档，**When** 用户尝试新增区域，**Then** 系统拒绝操作。

### US-LOC-003 查看位置详情

> 作为运维管理员，我希望查看机房和区域详情并继续浏览其下级对象，以便理解物理位置层级。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | LOC-005 |
| 依赖 | US-LOC-001、US-LOC-002 |

验收标准：

1. **Given** 机房存在，**When** 用户从位置列表查看机房，**Then** 详情展示编码、描述、区域数量和机柜数量。
2. **Given** 机房下存在区域，**When** 用户查看机房详情，**Then** 可以继续进入任一区域详情。
3. **Given** 区域存在，**When** 用户查看区域，**Then** 详情展示所属机房、编码、描述、机柜数量和总 U 数。
4. **Given** 区域下存在机柜，**When** 用户查看区域详情，**Then** 可以继续进入任一机柜详情。

## 5. EPIC-RACK：管理机柜

### US-RACK-001 创建机柜

> 作为运维管理员，我希望从常见规格或自定义规格创建机柜，以便准确表达现场机柜容量。

| 属性 | 内容 |
|---|---|
| 优先级 | P0；自定义规格为 P1 |
| 来源需求 | RACK-001、RACK-002、RACK-003、RACK-004、RACK-008 |
| 依赖 | US-LOC-002 |

验收标准：

1. **Given** 存在活动区域，**When** 用户填写唯一机柜编码并选择 42U，**Then** 系统创建机柜且总 U 数为 42。
2. **Given** 用户打开规格选择，**Then** 系统提供 18U、22U、27U、32U、37U、42U、45U 和 47U。
3. **Given** 用户选择自定义规格，**When** 输入合法总 U 数，**Then** 系统按该数值创建机柜。
4. **Given** 同一区域已存在相同编码，**When** 用户保存，**Then** 系统拒绝保存并标记编码冲突。
5. **Given** 不同区域存在相同编码，**When** 用户保存，**Then** 系统允许创建。

### US-RACK-002 编辑和归档机柜

> 作为运维管理员，我希望修正机柜信息并归档停用机柜，以便台账与现场状态一致。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | RACK-001、RACK-005；派生规则 DR-002、DR-003 |
| 依赖 | US-RACK-001 |

验收标准：

1. **Given** 机柜没有越界风险，**When** 用户修改编码、规格或备注并保存，**Then** 列表和机柜画布显示最新信息。
2. **Given** 缩小总 U 数会使现有设备越界，**When** 用户保存，**Then** 系统拒绝修改并列出受影响的设备及 U 位。
3. **Given** 机柜中存在当前上架设备，**When** 用户尝试归档，**Then** 系统拒绝操作并提示先移动或下架设备。
4. **Given** 机柜为空，**When** 用户确认归档，**Then** 机柜退出默认活动视图但历史记录保留。

### US-RACK-003 查看机柜容量信息

> 作为运维管理员，我希望查看机柜已占用、空闲容量和额定功率，以便判断是否可以继续上架设备。

| 属性 | 内容 |
|---|---|
| 优先级 | 容量 P1；额定功率 P2 |
| 来源需求 | RACK-006、RACK-007 |
| 依赖 | US-RACK-001、US-PLC-001 |

验收标准：

1. **Given** 机柜存在若干当前放置记录，**When** 用户查看机柜，**Then** 系统展示正确的已占用 U 数、空闲 U 数和占用率。
2. **Given** 设备被移动或下架，**When** 操作成功，**Then** 容量指标立即按最新数据重新计算。
3. **Given** 用户填写额定功率或备注，**When** 保存，**Then** 信息可以在机柜详情中查看和修改。

### US-RACK-004 查看机柜详情

> 作为运维管理员，我希望查看机柜完整信息和当前设备，以便核对容量与上架内容。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | RACK-009 |
| 依赖 | US-RACK-001、US-RACK-003 |

验收标准：

1. 详情展示位置、规格、总 U 数、额定功率、状态和备注。
2. 详情展示设备数量、已占用、可用容量和占用率。
3. 当前设备列表展示名称、类型、状态和 U 位，并可进入资产详情。
4. 用户可以从详情返回列表或在画布中查看所属区域。

## 6. EPIC-AST：管理设备资产

### US-AST-001 创建设备

> 作为资产管理员，我希望登记服务器和网络设备，以便建立统一的物理设备台账。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | AST-001、AST-002、AST-003、AST-004、AST-005、AST-008 |
| 前置条件 | 无需先选择机柜 |

验收标准：

1. **Given** 用户创建资产，**When** 选择设备类型，**Then** 可选项仅包含服务器、交换机、路由器和防火墙。
2. **Given** 用户填写名称、类型和占用高度，**When** 其他可选字段为空且数据合法，**Then** 系统允许创建未上架设备。
3. **Given** 用户未填写占用高度，**When** 创建表单初始化，**Then** 默认值为 1U。
4. **Given** 高度小于 1U，**When** 用户保存，**Then** 系统拒绝保存并提示合法范围。
5. **Given** 非空主机名、内网 IP 或 SN 与已有设备重复，**When** 用户保存，**Then** 系统按对应字段拒绝保存。
6. **Given** 创建成功，**Then** 设备初始状态可选择在用、维护或离线，并可以保持未上架。

### US-AST-002 编辑、归档设备

> 作为资产管理员，我希望更新或归档设备，以便台账反映设备生命周期变化。

| 属性 | 内容 |
|---|---|
| 优先级 | 编辑 P0；归档历史 P1 |
| 来源需求 | AST-001、AST-003、AST-004、AST-007；派生规则 DR-006 |
| 依赖 | US-AST-001 |

验收标准：

1. **Given** 设备存在，**When** 用户修改资产字段并保存，**Then** 详情和列表显示最新值。
2. **Given** 修改后的主机名、内网 IP 或 SN 冲突，**When** 用户保存，**Then** 系统拒绝修改且原数据保持不变。
3. **Given** 已上架设备，**When** 用户选择归档，**Then** 系统明确提示当前 U 位将被释放并要求确认。
4. **Given** 用户确认归档，**Then** 设备状态变为已归档、当前 U 位释放、历史放置记录保留。
5. **Given** 设备已经归档，**When** 用户尝试上架，**Then** 系统拒绝操作。

### US-AST-003 搜索和筛选设备

> 作为资产管理员，我希望快速搜索和筛选设备，以便定位资产及其当前物理位置。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | AST-006 |
| 依赖 | US-AST-001 |

验收标准：

1. **Given** 设备台账中存在多条数据，**When** 用户输入主机名、IP、SN 或型号关键字，**Then** 结果在 300 毫秒目标内更新。
2. **Given** 用户选择类型、状态、机房、区域或机柜筛选，**When** 条件生效，**Then** 只显示同时满足条件的设备。
3. **Given** 设备未上架，**When** 用户选择“未上架”，**Then** 系统显示没有当前放置记录的活动设备。
4. **Given** 没有匹配结果，**Then** 系统显示空状态并允许清除筛选条件。

### US-AST-004 查看设备详情

> 作为资产管理员，我希望查看设备完整字段及当前位置，以便核对设备身份和物理归属。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | AST-009 |
| 依赖 | US-AST-001 |

验收标准：

1. 详情展示类型、状态、高度、用途、厂商、型号、主机名、内网 IP、管理 IP、SN 和备注。
2. **Given** 设备已上架，**Then** 详情展示机房、区域、机柜和完整 U 位范围，并可进入关联详情。
3. **Given** 设备已上架，**When** 用户选择在画布中定位，**Then** 画布切换到对应区域并选中该设备。
4. **Given** 设备未上架，**Then** 详情明确显示未上架状态并提供上架入口。

## 7. EPIC-PLC：管理 U 位放置

### US-PLC-001 通过表单上架设备

> 作为运维管理员，我希望通过表单把未上架设备放到指定机柜 U 位，以便记录真实物理位置。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | PLC-001、PLC-005、PLC-006 |
| 依赖 | US-RACK-001、US-AST-001 |

验收标准：

1. **Given** 设备未上架且设备、机柜均为活动状态，**When** 用户选择机柜和起始 U 位，**Then** 表单在保存前显示完整占用范围。
2. **Given** 设备高度为 4U 且起始位置为 U19，**Then** 表单显示占用 U19–U22。
3. **Given** 目标范围合法且空闲，**When** 用户保存，**Then** 系统创建唯一当前放置记录并刷新机柜画布。
4. **Given** 设备已有当前放置记录，**When** 用户再次执行上架，**Then** 系统引导使用“移动”而不是创建第二条当前记录。
5. 未上架设备的首次上架仍通过表单完成，画布拖动只调整已上架设备。

### US-PLC-002 阻止越界和 U 位冲突

> 作为运维管理员，我希望系统阻止非法放置，以便机柜台账不会出现重叠或越界。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | PLC-003、PLC-004、PLC-005 |
| 依赖 | US-PLC-001 |

验收标准：

1. **Given** 机柜总高 42U，**When** 设备占用范围低于 U1 或高于 U42，**Then** 系统拒绝保存并标明合法范围。
2. **Given** U19–U22 已被占用，**When** 新设备范围与其部分或全部重叠，**Then** 系统拒绝保存并显示冲突设备和 U 位。
3. **Given** 新设备紧邻已有设备但不重叠，**When** 用户保存，**Then** 系统允许上架。
4. **Given** 前端校验被绕过，**When** 后端收到非法范围，**Then** 后端仍拒绝写入且数据库数据不变。

### US-PLC-003 原子移动设备

> 作为运维管理员，我希望把设备移动到新的机柜或 U 位，以便一次操作完成位置变更且失败时保留原位置。

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源需求 | PLC-002、PLC-003、PLC-004、PLC-005、PLC-006、AUD-001 |
| 依赖 | US-PLC-001、US-PLC-002 |

验收标准：

1. **Given** 设备已有当前位置，**When** 用户选择新机柜和起始 U 位，**Then** 保存前显示旧位置和新占用范围。
2. **Given** 新范围合法且空闲，**When** 用户确认移动，**Then** 原位置释放、新位置生效且只存在一条当前放置记录。
3. **Given** 新范围冲突、越界或保存失败，**When** 移动结束，**Then** 原位置保持不变。
4. **Given** 移动成功，**Then** 操作记录包含变更前后机柜及 U 位。

### US-PLC-004 下架设备并保留历史

> 作为运维管理员，我希望下架设备但保留历史位置，以便释放容量并能够追溯变化。

| 属性 | 内容 |
|---|---|
| 优先级 | 下架 P0；历史查看 P1 |

## 14. Definition of Ready

用户故事进入开发前应满足：

- 用户价值、边界和优先级清楚。
- 验收标准可以被测试，不依赖“效果较好”等主观描述。
- 依赖故事已完成，或已明确同一迭代交付。
- 涉及数据结构或 IPC 契约时，技术方案已经评审。
- 涉及破坏性操作时，确认、失败恢复和审计行为已经明确。
- UI 故事具备对应线框或交互说明。

## 15. Definition of Done

用户故事完成必须满足：

- 所有验收标准通过，并覆盖成功、边界和失败路径。
- 前端和 Rust 后端均执行其职责范围内的输入校验。
- 数据写入具备必要事务和审计记录。
- 单元、集成或界面测试按风险补齐且通过。
- 没有引入 PRD 非目标中的远程监控、同步或多用户能力。
- 相关 PRD、技术设计和用户故事文档保持一致。
- macOS 本地构建通过，核心界面无阻断错误。
