# Iteration 005：核心交互重构

## 1. 迭代目标

重新以“用户能否连续完成一件事”评估已有页面，修复画布、详情、列表和表单之间的上下文丢失，并交付日常设备维护必需的搜索、移动和下架闭环。

## 2. 实现范围

- 用受校验的 `returnTo` 恢复画布筛选、列表搜索和详情发起位置，拒绝外部或 scheme-relative 路径。
- 从机房、区域和机柜上下文发起新建时预选已知父级；机柜下新建设备后直接进入已预选机柜的上架页。
- 机房、区域、机柜和设备详情提供新增下级对象、查看画布、选择已有设备、移动及下架等上下文动作。
- 机房与区域多选改为受控 Popover；同时只打开一个，支持 Esc、点击外部和明确的清除/完成动作。
- 设备列表增加组合搜索、类型、状态和上架状态筛选，并与机柜列表一样支持整行和键盘 Enter 导航。
- 上架/移动页显示可容纳当前设备的连续空闲范围、最终占用范围和具体冲突设备。
- 新增 `move_asset` 与 `unplace_asset` 类型化 IPC；移动在同一 SQLite 事务中结束原位置并创建新位置，下架只结束当前放置并保留历史行。

## 3. 非目标

- 不实现归档、审计日志界面或历史放置查询。
- 不增加设备拖拽上架/移动、画布虚拟化、Excel 导入导出或备份恢复。
- 不改变单机、单用户和本地优先的产品边界。

## 4. 自动化验证

- Rust 应用层测试覆盖成功移动、下架、历史行保留、移动冲突回滚和原位置未变拒绝。
- React 测试覆盖安全返回路径、设备搜索/筛选、上下文机柜选择、连续空闲范围、冲突拦截和受控筛选弹层。
- 功能 worktree 和 squash 后的 `main` 均必须执行完整 `pnpm gate`。

## 5. 验收结果

- 功能 worktree 的 `pnpm gate` 已通过：文档、bindings、ESLint、TypeScript、37 个 Vitest、前端构建、Rust format、Debug Clippy、Release check 和 15 个 Rust 测试全部通过。
- 使用独立 `com.whg517.uframe.uxqa` 数据目录的 `UFrame UX QA.app` 在 1280×800 真实 Tauri 窗口中验证，未修改正式 UFrame 数据。
- 空库从机柜画布进入创建链路，实际完成“机房 → 区域 → 机柜”；新区域自动预选刚创建的机房，新机柜自动预选刚创建的区域。
- 机柜详情的“新建设备”实际创建 2U 设备并直接进入目标机柜已预选的上架页；页面显示 `U1–U42` 连续空闲范围和最终 `U10–U11`。
- 实际打开机房筛选后切换到区域筛选，前一弹层会立即关闭，不再发生重叠；空选择表示全部，清除和完成动作可见。
- 实际将订单服务器从 `A-01 · U10–U11` 移动到 `A-01 · U20–U21`；保存后返回原区域画布，设备保持选中，画布与侧栏同时显示新 U 位。
- 实际从画布侧栏打开下架确认，完成后设备从机柜消失，设备台账显示“未上架”；主机名 `order-01` 搜索成功且条件保存在 URL。
- 画布、筛选弹层、机柜详情、上架/移动表单、下架 Sheet 和设备列表在 1280×800 下无溢出、遮挡或必须绕行的操作。

## 6. 文案回归

- 移除所有正式页面中 `Physical assets`、`Rack inventory`、`Location` 等仅用于原型分类的英文 eyebrow，避免与中文标题重复。
- `PageHeader` 不再接受 eyebrow 属性，从组件契约上防止同类原型注释回归。
