## 1. 迭代目标

让用户在机柜一览中直接拖动已上架设备调整 U 位，通过显式的编辑模式先预览多项变更，再统一保存确认。

## 2. 实现范围

- 设备可在同一机柜内或跨可见机柜拖动；拖动时保留指针在设备上的抓取偏移。
- 首次拖动自动进入布局编辑模式；也可以从工具栏显式进入。
- 画布使用草稿投影立即显示调整后布局、待保存设备数和目标 U 位范围。
- 目标范围越界或与草稿布局重叠时拒绝放下，并在目标位置显示冲突提示。
- “取消”只丢弃前端草稿；“保存调整”通过 `move_assets` 一次提交所有变更。
- Rust 先构建和验证整个最终活动布局，再在同一 SQLite 事务中结束旧放置、创建新放置，支持联动移位并在任一失败时整体回滚。
- 设备布局编辑期间暂停机柜排序，保留缩放操作，避免拖动手势冲突。

## 3. 非目标

- 不实现将未上架设备从台账拖入机柜，首次上架仍使用表单。
- 不实现自动排布、多选框选、撤销/重做历史或触摸屏手势。
- 不改变单设备精确移动表单、机柜排序持久化和单机本地数据边界。

## 4. 自动化验证

- 纯函数测试覆盖抓取偏移、缩放无关的 U 位换算、跨机柜草稿投影、恢复原位和冲突提示。
- React 测试覆盖拖动自动进入编辑、保存前不调用 IPC、统一保存及成功后退出编辑。
- Rust 应用层测试覆盖多设备交换成功和批量冲突整体回滚。
- 功能 worktree 和 squash 后的 `main` 都执行完整 `pnpm gate`。

## 5. 验收结果

- 功能 worktree 的 `pnpm gate` 已通过：文档追踪、bindings 一致性、ESLint、TypeScript、44 个 Vitest、前端构建、Rust format、Debug Clippy、Release check 和 17 个 Rust 测试全部通过。
- React 页面级拖放测试验证：不先点击“编辑布局”时，直接将设备从 A-01 拖到 B-01 的 U7 会自动进入编辑；保存前不调用 IPC，确认时仅提交最终草稿。
- Rust 应用层测试验证两台设备交换位置可原子成功；批量最终布局存在重叠时，所有原放置均保持有效。
- 在真实 Debug Tauri 窗口中使用当前 B01 42U 机柜验证：直接拖动 S001 会显示“布局编辑中”，机房/区域筛选与机柜排序被禁用，保存在无草稿时不可用。
- 在同一真实窗口选择“取消”后恢复普通画布，S001 仍位于 B01 的 U2–U3，未触发保存，不修改正式 UFrame 数据。
