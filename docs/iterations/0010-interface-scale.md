# Iteration 010：界面密度与字号

| 属性 | 内容 |
|---|---|
| 状态 | Implemented / Verified |
| 日期 | 2026-09-09 |
| 分支 | `feat/interface-scale` |
| 用户故事 | US-SET-004 |
| 需求 | SET-004–SET-005、SET-007 |

## 1. 目标

让用户根据屏幕尺寸、观看距离和信息容量偏好，独立调整全应用的内容密度和字号，同时保持机柜 U 位几何精度。

## 2. 交付范围

- 设置页增加“界面尺寸”区域。
- 界面密度支持紧凑、标准和宽松三档，通过 Tailwind 全局 spacing token 同步影响侧栏、页头、卡片、表单、列表和按钮。
- 界面字号支持小、标准和大三档，通过根节点字体基准统一影响文字和 rem 控件。
- 密度和字号即时生效并写入现有版本化本地偏好，不进入 SQLite 或 Tauri IPC。
- 旧版本偏好缺少字段、字段无效或存储损坏时逐字段回退到标准档。
- 恢复默认设置同时把密度和字号恢复为标准档。
- 简体中文和英语界面文案保持完整对应。

## 3. 明确未纳入

- 用户输入任意像素字号或间距比例。
- 针对单个页面保存独立密度或字号。
- 改变机柜 U 位高度、设备边界或拖动几何。
- 默认启动页面、数据目录和备份位置。

## 4. 验证证据

- `pnpm gate`：2026-09-09 通过；文档、版本、bindings、ESLint、TypeScript、前端测试、生产构建、Rust format、Debug/Release Clippy 和 Rust 全量测试全部通过。
- React 自动化测试：覆盖密度与字号选择、根节点属性、即时持久化、恢复默认、旧偏好缺失和无效值回退。
- 生产 CSS 产物检查：包含三档 `data-density` spacing token 和三档 `data-font-size` 根字体基准。
- Tauri Debug `.app` 真实桌面检查：设置页在宽松密度与大字号组合下无卡片或按钮溢出；机柜一览侧栏、页头和筛选保持对齐，U 位与设备边界不变；检查后恢复原标准密度和字号。
- 本轮不修改数据库 schema、业务数据、Tauri Command 或 IPC bindings；机柜几何继续使用固定像素常量。

## 5. 结果

Iteration 010 完成 US-SET-004。用户可以独立组合界面密度与字号，所有使用语义 spacing 和 rem 的界面统一响应，而机柜 U 位及设备拖动计算保持不变。
