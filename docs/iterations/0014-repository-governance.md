## 1. 评审方法与边界

对照 PRD/用户故事、技术设计和现有代码，检查责任划分、依赖方向、状态所有权、事务失败行为以及规范是否有自动控制。不是新增业务迭代，不改变 IPC/schema，不包含备份、数据迁移、恢复或数据库路径配置。

前端复核 app/features/shared 依赖、查询缓存、表单快照和画布草稿，保留 Iteration 013 已验证的边界；本轮优先修复后端仍然存在的传输/存储耦合，而非为统一目录大规模搬动组件。

## 4. 后续事项与关闭条件

| 项目 | 保留原因 | 后续关闭条件 |
|---|---|---|
| 普通 CRUD 和单设备放置的应用层 SQL | 控制本轮回归面，先完成高风险事务切片 | 按用例迁移到应用自有端口，并保留行为/失败测试 |
| Domain 独立 crate | 当前纯模块已经有独立编译控制，无需新增构建层 | 规模或独立复用需要时另立 ADR |
| 全量布局扫描与大规模画布 | 尚无性能瓶颈测量，不推测收益 | 使用实际数据量和延迟评估，再优化并证明冲突校验等价 |
| 分支保护与发行安装证明 | 套餐/凭据/双架构机器是外部前提 | 获得授权和前提后通过真实 PR/发行验收；不能靠文档标记关闭 |
| Actionlint/SAST/依赖供应链扫描 | 本轮实现项目特定工作流政策与失败测试，不声称全面扫描 | 单独评估工具、误报成本和托管能力，再建立可重复门禁 |
